# 实战型定向股票投研系统重构方案

> 版本日期：2026-06-08  
> 新项目定位：家庭股票池的定向深度投研、持仓/关注复盘、风险提醒和情景路径推演。  
> 旧项目定位：实验原型、数据源验证、算法试验场和代码参考库。  
> 重要边界：系统辅助研究和复盘，不替用户做交易决定，不输出自动买卖指令。

## 1. 为什么建议新开项目

当前项目已经完成了大量探索：

- 真实行情和 K 线数据接入。
- A 股全市场覆盖宇宙、候选池、研究队列。
- 财务、估值、公告、技术结构、缠论雏形。
- 家庭持仓分析。
- 数据健康检查。
- 自动化测试体系。

这些能力证明方向是可行的，但当前页面和数据结构已经承载了太多探索痕迹。继续在旧项目上叠加功能，会让系统越来越像“实验室大拼盘”，不利于形成一个清晰、稳定、可长期使用的实战产品。

因此建议：

- 旧项目保留，作为原型仓库和算法试验场。
- 新项目重新设计，作为正式使用的投研系统。
- 不从零浪费已有成果，而是选择性迁移旧项目中最有价值的能力。

## 2. 从旧项目提炼出的最有价值资产

### 2.1 数据同步能力

已验证有价值：

- A 股真实行情快照。
- 日线 K 线。
- 周线聚合。
- 60 分钟 K 线。
- 财务指标。
- 派生估值指标。
- 公告事件。
- 数据更新时间和数据健康状态。

新项目应保留这些能力，但围绕“家庭股票池”同步，而不是一开始就全市场大规模同步。

### 2.2 缠论分析雏形

已验证有价值：

- 分型。
- 笔。
- 中枢。
- 背驰候选。
- 一买、二买、三买候选。
- 风险卖点候选。
- 周线、日线、60 分钟联动判断。

新项目中，缠论不应作为神秘买卖信号，而应作为“结构分析层”：

- 判断当前处于上升、震荡、修复还是风险结构。
- 提示买点候选是否需要确认。
- 提醒风险卖点是否扩大。
- 给情景路径图提供关键条件。

### 2.3 数据健康意识

这是旧项目中非常重要的经验。

以后每个结论前都必须先回答：

- 行情是否最新？
- 日线是否足够长？
- 周线是否可用？
- 60 分钟线是否可用？
- 财务数据是否完整？
- 公告是否同步？
- 结论可信度是否受数据缺口影响？

没有数据健康层，任何“智能判断”都会变成不可靠的幻觉。

### 2.4 结论层表达

旧项目从单纯分数，逐步演化出了更接近实战的结论：

- 可小仓试探。
- 可分批建仓。
- 可加仓观察。
- 买点确认，进入执行观察。
- 可继续持有。
- 只观察不加仓。
- 等待二买确认。
- 出现风险卖点需减仓观察。
- 风险复盘。
- 先补齐数据。
- 不适合追高。

新项目应继续强化这种语言。用户最终需要的是“现在怎么理解这只股票”，不是一个孤立的分数。

### 2.5 家庭股票池

爸爸的使用场景说明：用户可能只给股票代码，不录入成本、仓位和买入理由，也希望系统直接分析。

新项目不再区分“我的股票”和“爸爸的股票”，而是统一成家庭股票池：

- 家庭共同关注的股票统一管理。
- 每只股票只要输入代码，就进入深度分析。
- 不强制录入成本、仓位和买入理由。
- 用状态和标签区分用途，例如已持有、观察中、准备研究、暂停跟踪、爸爸关注、我关注、红利、AI、医药、风险复盘。
- 家庭股票池不等于全市场候选池，候选发现必须经过人工确认后才加入。

### 2.6 动态股票池能力

动态股票池仍然有价值，但它不应是新项目主产品。

新项目中建议把它降级为“候选发现”：

- 每天或每周从全市场发现少量候选。
- 只推荐值得加入家庭股票池的线索。
- 必须解释为什么值得加入。
- 不直接替代用户的定向研究列表。

## 3. 新项目核心定位

新项目建议定位为：

> 输入家庭关注股票，系统持续同步真实数据，并生成可用于实战复盘的深度分析、风险提醒、买点观察和情景路径推演。

它解决的问题不是“今天全市场哪只股票最容易涨”，而是：

- 我关心的股票现在处于什么状态？
- 是否值得继续持有、观察、等待或复盘风险？
- 当前结论依赖哪些数据？
- 缠论结构是否支持行动，还是只支持继续观察？
- 估值是否有赔率？
- 公告或财报是否改变投资逻辑？
- 未来几种可能走势分别要看什么关键条件？

## 4. 产品原则

### 4.1 定向优先

系统优先服务用户指定股票：

- 家庭已持有股票。
- 家庭重点观察股票。
- 家庭计划研究股票。
- 用户临时输入股票。
- AI 从候选发现中建议加入的股票。

全市场海选只作为补充，不作为主页面中心。

### 4.2 深度优先

宁可少分析几只股票，也要把每只股票分析深。

每只家庭股票池股票最终至少要覆盖：

- 行情。
- 日 K。
- 周 K。
- 60 分钟 K。
- 财务。
- 估值。
- 公告。
- 行业。
- 缠论结构。
- 结论层。
- 情景路径。

### 4.3 可解释优先

系统每个结论都必须说明：

- 基于什么数据。
- 用了什么算法。
- 关键证据是什么。
- 最大风险是什么。
- 什么条件会让结论改变。

### 4.4 提醒变化，而不是堆积信息

每天最重要的不是重新读完整报告，而是知道：

- 哪只股票发生了关键变化。
- 哪个价格位被突破或跌破。
- 哪条投资逻辑被增强或削弱。
- 是否出现新的买点候选或风险卖点。
- 数据是否过期导致结论不能用了。

## 5. 新系统核心模块

## 5.1 今日工作台

目标：每天打开系统后，只看最重要的事情。

内容：

- 今日风险提醒。
- 今日机会观察。
- 数据同步异常。
- 关键价位触发。
- 公告/财报变化。
- 缠论结构变化。
- 需要人工复盘的股票。

典型提醒：

- 海光信息：出现高优先级风险信号，先复盘是否破坏持仓逻辑。
- 深南电路：价格接近强弱分界，观察是否有效站稳。
- 某股票：60 分钟出现底背驰候选，但日线仍未确认。
- 某股票：公告事件影响核心假设，需要重新阅读。

## 5.2 家庭股票池

目标：维护家庭真正关心的股票，而不是海量股票池。

状态建议：

- 已持有。
- 观察中。
- 准备研究。
- 候选发现待确认。
- 暂停跟踪。

标签建议：

- 爸爸关注。
- 我关注。
- 红利。
- AI。
- 半导体。
- 医药。
- 新能源。
- 风险复盘。

每只股票显示：

- 股票名称和代码。
- 状态。
- 标签。
- 当前结论。
- 数据健康状态。
- 当前价格。
- 关键价位。
- 缠论状态。
- 估值状态。
- 最近变化。
- 下一步动作。

## 5.3 单股深度分析页

这是新项目最核心的页面。

建议页面结构：

1. 顶部结论区
   - 当前结论。
   - 置信度。
   - 数据健康状态。
   - 最重要的下一步动作。

2. 关键价位区
   - 当前价格。
   - 强弱分界。
   - 中期防守。
   - 追高风险区。
   - 观察买点区。
   - 失效位。

3. 情景路径图
   - 强势路径。
   - 震荡路径。
   - 风险路径。
   - 每条路径的成立条件和失效条件。

4. 缠论结构区
   - 周线方向。
   - 日线中枢。
   - 60 分钟买点/卖点候选。
   - 背驰/盘整背驰。
   - 一买/二买/三买候选。
   - 风险卖点。

5. 基本面区
   - 行业逻辑。
   - 公司质量。
   - 业绩兑现。
   - 财务质量。
   - 竞争优势。

6. 估值区
   - PE/PB/PS/PEG。
   - 历史分位。
   - 同业比较。
   - 三情景估值。
   - 安全边际。

7. 事件和公告区
   - 最新公告。
   - 财报摘要。
   - 风险公告。
   - 回购、减持、分红、订单、问询函。

8. 复盘记录区
   - 系统结论历史。
   - 用户人工判断。
   - 关键假设变化。
   - 曾经触发但失败的信号。

## 5.4 家庭股票池使用方式

目标：服务家庭共同投研。无论股票来自自己、爸爸或其他家庭成员，系统都只围绕股票本身做深度分析。

原则：

- 家庭股票池是新项目的主股票池。
- 不和候选发现自动混合。
- 不要求录入成本、仓位、买入理由。
- 可以只输入股票代码。
- 系统自动补齐行情、K 线、财务、估值、公告和缠论结构。
- 用状态和标签表达“为什么关注”，而不是用多个投资者账户拆分。

输出风格要更直接：

- 这只股票现在主要风险是什么？
- 是否适合继续持有？
- 是否不适合加仓？
- 是否只是观察，不该急着买？
- 哪个价位跌破要复盘？
- 哪个结构确认后才值得重新看机会？

## 5.5 数据同步中心

目标：让用户知道结论是否可信。

每只股票显示：

| 数据类型 | 状态 | 用途 |
|---|---|---|
| 实时/准实时行情 | 最新 / 过期 / 缺失 | 当前价格和涨跌幅 |
| 日线 K | 完整 / 不足 / 缺失 | 趋势、均线、中枢 |
| 周线 K | 完整 / 不足 / 缺失 | 大级别方向 |
| 60 分钟 K | 完整 / 不足 / 缺失 | 买点、卖点、背驰确认 |
| 财务 | 完整 / 不足 / 缺失 | 公司质量和业绩兑现 |
| 估值 | 完整 / 不足 / 缺失 | 赔率和安全边际 |
| 公告 | 最新 / 未同步 / 解析失败 | 事件和逻辑变化 |

数据同步中心必须支持：

- 单只股票同步。
- 一组股票同步。
- 每日全量同步家庭股票池。
- 显示最后更新时间。
- 显示数据源。
- 显示失败原因。

## 5.6 候选发现

目标：保留旧项目的全市场扫描能力，但不让它干扰主流程。

候选发现只回答：

- 今天有哪些股票值得加入家庭股票池？
- 为什么值得加入？
- 数据是否足够？
- 属于哪个行业和逻辑？
- 是估值机会、结构机会、事件机会，还是基本面改善？

候选发现的输出数量要少。

建议：

- 每日最多 5-10 只。
- 每周最多 20 只。
- 每只必须有“加入理由卡”。
- 人工确认后才进入家庭股票池。

## 6. 情景路径图设计

不建议叫“预测走势图”，建议叫：

- 情景路径图。
- 推演走势图。
- 三路径观察图。

原因：系统不应该假装能精准预测未来价格。更实战的方式是基于现有数据给出几种可能路径，并明确每条路径的成立条件和失效条件。

### 6.1 三条路径

#### 强势路径

含义：

- 股价站上关键压力。
- 回踩不跌回中枢。
- 60 分钟或日线出现买点确认。
- 成交或基本面事件配合。

系统表达：

- “若站上强弱分界并回踩不破，强势路径成立。”
- “若 60 分钟出现二买确认，可进入重点观察。”

#### 震荡路径

含义：

- 股价在中枢区间、均线区间或估值区间内波动。
- 方向未确认。
- 不适合追高，也不适合过度悲观。

系统表达：

- “当前仍处于中枢震荡，等待方向选择。”
- “适合观察，不适合扩大仓位。”

#### 风险路径

含义：

- 跌破关键支撑。
- 中枢下移。
- 出现顶背驰或风险卖点扩大。
- 公告/财报破坏核心逻辑。

系统表达：

- “若跌破中期防守位，风险路径成立。”
- “若风险卖点继续扩大，持仓优先控制回撤。”

### 6.2 图上应展示的元素

情景路径图应展示：

- 当前价格。
- 最近中枢区间。
- 强弱分界。
- 中期防守。
- 追高风险区。
- 一买候选区。
- 二买候选区。
- 三买候选区。
- 风险卖点。
- 20/60/120 个交易日观察窗口。
- 强势、震荡、风险三条路径。

### 6.3 关键原则

- 图不是算命。
- 图是决策地图。
- 每条线都必须有条件。
- 每个条件都必须来自数据或算法。
- 如果数据不足，路径图必须标注“不足以判断”。

## 7. 市场适配层：A 股优先，美股经验本土化

新项目第一阶段应明确只服务 A 股。美股优秀投资者和交易员经验可以进入方法论库，但不能生硬套到 A 股结论里。

系统在生成结论前，必须先识别市场：

```text
股票代码 -> 识别市场 -> 选择数据源 -> 使用市场规则 -> 调整框架权重 -> 生成结论
```

### 7.1 A 股第一阶段规则

A 股结论引擎必须考虑：

- T+1 交易制度。
- 涨跌停限制。
- 散户占比高，题材和情绪波动更强。
- 政策、产业方向、监管公告影响更大。
- 巨潮、交易所、东方财富等公告和财务数据源。
- 估值常有行业主题溢价，不能直接套用美股 PE/PS 标准。
- 60 分钟买点必须考虑次日才能卖出的风险。
- 涨停后的突破不能按普通突破理解，要看封单、换手和次日承接。
- 宽基指数、市场成交额、行业轮动和题材退潮对个股结论影响很大。

### 7.2 美股经验如何使用

美股经验用于方法论参考，而不是直接替 A 股下结论。

可借鉴：

- CAN SLIM 的业绩加速和相对强弱。
- Minervini VCP 的波动收缩和突破结构。
- Stan Weinstein 的阶段分析。
- Livermore 的趋势跟随和风险控制。
- Wyckoff 的吸筹、洗盘、派发和量价行为。
- Howard Marks 的周期和风险补偿。
- Soros 反身性对大主题和泡沫阶段的解释。

本土化方式：

- 美股 breakout 在 A 股中要结合涨停、换手、封单和次日承接。
- VCP 在 A 股中要加入涨跌停和题材拥挤度。
- CAN SLIM 在 A 股中要结合政策周期、公告质量和财报可信度。
- 趋势跟随在 A 股中要更重视题材退潮和流动性变化。

### 7.3 未来扩展顺序

建议顺序：

1. 第一阶段只做 A 股。
2. A 股结论引擎稳定后，再扩展美股。
3. 港股和中概作为独立市场适配，不和 A 股、美股混用一套规则。

## 8. 最终结论决策器

新项目会融合多个框架，但最终必须归纳为一个清晰结论。最终结论不是多个算法简单平均，而是一个有优先级的决策流程。

建议决策链：

```text
数据健康 -> 风险一票否决 -> 基本面逻辑 -> 估值赔率 -> 技术结构 -> 市场环境 -> 外部经验共振 -> 最终结论
```

### 8.1 数据健康先行

如果关键数据缺失，系统不能强行输出买入类结论。

典型输出：

- 数据不足，暂不下结论。
- 先补齐 60 分钟 K 线后再判断买点。
- 财务和公告缺失，只能做技术观察，不能做完整结论。

### 8.2 风险一票否决

如果出现重大风险，即使其他模块很好，也不能输出买入类结论。

一票否决包括：

- 财务造假或重大会计风险。
- 业绩暴雷。
- 核心逻辑证伪。
- 重大减持、监管处罚、重大诉讼。
- 跌破中期防守位并无法收回。
- 风险卖点扩大。
- 市场环境进入明显防守期，个股又处于高估和高拥挤状态。

### 8.3 多框架共振

只有多个框架同时支持，系统才可以给出正向机会类结论。

示例：

```text
结论：可分批建仓

原因：
1. 基本面逻辑未破坏，业绩兑现仍在。
2. 估值处于可接受区间。
3. 日线回踩不破中枢，60 分钟出现买点确认。
4. 风险收益比大于 2:1。
5. 当前市场环境支持成长股进攻。

失效条件：
1. 跌破中期防守位。
2. 财报低于预期。
3. 风险卖点继续扩大。
```

### 8.4 动作分级

系统不应该只输出“买或不买”，而要输出动作强度：

- 只观察。
- 小仓试探。
- 分批建仓。
- 加仓复核。
- 继续持有。
- 减仓观察。
- 退出观察。

动作越积极，要求的数据健康、风险收益比和多框架共振越高。

## 9. 动态方法论与复盘升级机制

市场一直变化，系统的方法论不能写死。新项目需要一个可版本化、可复盘、可升级的方法论引擎。

### 9.1 方法论框架库

建议纳入：

- 缠论结构模块。
- CAN SLIM 成长动量模块。
- VCP 波动收缩模块。
- 阶段分析模块。
- Wyckoff 量价结构模块。
- 估值安全边际模块。
- 周期位置模块。
- 风险控制模块。
- 行业生命周期模块。
- A 股市场情绪和涨跌停承接模块。

每个模块输出：

- 当前判断。
- 证据。
- 置信度。
- 失效条件。
- 适用市场。
- 适用行业。

### 9.2 外部经验与 X.com 叙事层

可以从 X.com、优秀交易员、投资者、基金经理和行业专家中提炼经验，但不能直接跟单。

使用方式：

- 作为市场叙事雷达。
- 作为方法论更新来源。
- 作为风险提示来源。
- 作为交易纪律和复盘方法参考。

可信度分层：

| 来源 | 权重 | 用途 |
|---|---:|---|
| 经典投资方法论 | 高 | 长期原则和框架 |
| 长期验证过的交易员经验 | 中高 | 交易结构、风险控制、复盘方法 |
| 当前市场叙事 | 中低 | 行业热度、共识变化、情绪观察 |
| 短期喊单观点 | 低 | 只做情绪参考，不进入结论核心 |

### 9.3 市场环境识别

同一只股票，在不同市场环境下应该使用不同阈值。

系统应识别：

- 牛市进攻。
- 熊市防守。
- 震荡轮动。
- 流动性宽松。
- 流动性收紧。
- 主题泡沫。
- 产业趋势初期。
- 行业退潮。

例如：

- 进攻环境下，可以提高成长和动量权重。
- 防守环境下，提高现金流、估值安全边际和回撤控制权重。
- 主题泡沫阶段，降低追高结论概率，提高拥挤度和风险卖点权重。

### 9.4 方法论版本管理

每次算法或权重变化都必须留版本记录。

示例：

```text
decision_engine_v1.3
新增：A 股涨停承接规则
调整：AI 主题拥挤度权重 +5
降低：单纯估值便宜的权重
原因：近期题材波动加大，追高风险上升
```

版本记录至少包括：

- 版本号。
- 修改内容。
- 修改原因。
- 影响哪些行业或市场。
- 是否需要回测或人工复盘。

### 9.5 结论复盘机制

每个结论都要在后续被复盘。

复盘问题：

- 当时为什么这么判断？
- 后来验证了吗？
- 是数据错、算法错，还是市场环境变了？
- 哪个框架有效？
- 哪个框架误导了我们？
- 是否需要调整权重或新增规则？

这是系统长期变强的关键。

## 10. 单股结论标准

每只股票最终应输出一张“结论卡”。

格式：

```markdown
股票：
当前结论：
置信度：
数据健康：

一句话判断：

为什么：
1.
2.
3.

关键价位：
- 强弱分界：
- 中期防守：
- 追高风险：
- 买点观察：
- 失效位：

缠论结构：
- 周线：
- 日线：
- 60 分钟：
- 买点候选：
- 风险卖点：

下一步动作：
1.
2.
3.

什么情况会改变结论：
1.
2.
3.
```

结论枚举建议：

### 10.1 正向机会类

这类结论不是自动交易指令，而是表示系统认为买入、建仓或加仓的研究条件已经部分或较充分满足，需要用户进入最终人工决策。

| 结论 | 含义 |
|---|---|
| 可小仓试探 | 基本面逻辑未破坏，价格进入观察区，结构初步转强，但仍需严格控制仓位和失效位 |
| 可分批建仓 | 基本面、估值、结构和数据健康同时满足，适合按计划分批，而不是一次性重仓 |
| 可加仓观察 | 已持有股票逻辑增强，回踩不破关键位或出现买点确认，可进入加仓复核 |
| 买点确认，进入执行观察 | 缠论结构、关键价位和风险收益比满足，进入人工最终决策阶段 |
| 强机会，需人工复核 | 多模块共振明显，但波动或风险也较大，必须人工确认仓位、失效位和计划 |

### 10.2 持有和观察类

| 结论 | 含义 |
|---|---|
| 可继续持有 | 逻辑未破坏，结构和风险可接受，但不代表新增买入条件已经满足 |
| 只观察不加仓 | 逻辑仍在，但赔率或结构不足 |
| 等待二买确认 | 可能有机会，但需要小级别确认 |
| 等待三买确认 | 突破后回踩未确认，不提前假设成功 |
| 数据不足，暂不下结论 | 数据健康不支持判断 |

### 10.3 风险防守类

| 结论 | 含义 |
|---|---|
| 风险复盘 | 有事件、结构或估值风险，需要重新检查 |
| 出现风险卖点需减仓观察 | 风险结构已出现，持仓优先控制回撤 |
| 逻辑破坏，退出观察 | 核心假设被证伪或数据明显恶化，不再作为重点研究对象 |

## 11. 数据要求

### 11.1 最低可用数据

如果只做基础分析，至少需要：

- 股票代码。
- 股票名称。
- 当前价格。
- 最近 250 个交易日日线。
- 最近 60 个交易日成交量。
- 最新财务摘要。
- 最新公告列表。

### 11.2 缠论结构数据要求

要做较可靠的缠论分析，建议：

| 级别 | 最低要求 | 较好要求 |
|---|---:|---:|
| 日线 | 250 根 | 800 根以上 |
| 周线 | 80 根 | 200 根以上 |
| 60 分钟 | 300 根 | 1200 根以上 |

没有 60 分钟线时：

- 可以判断周线和日线大结构。
- 不能高置信判断一买、二买、三买的执行级别。
- 风险卖点只能作为日线级别或弱确认提示。

### 11.3 财务和估值数据要求

基本面和估值至少需要：

- 营收增长。
- 净利润增长。
- 毛利率。
- ROE/ROIC。
- 经营现金流。
- 资产负债率。
- PE/PB/PS。
- 历史估值分位。
- 同业估值比较。

不同行业必须使用不同指标：

- 银行看净息差、不良率、拨备覆盖率、资本充足率。
- 消费看品牌、毛利率、渠道和现金流。
- 科技看研发、收入兑现、客户和产品周期。
- 新能源看供需、库存、价格、产能和盈利周期。
- 红利股看股息率、现金流、分红稳定性和估值。

## 12. 新项目建议页面结构

建议第一版页面：

```text
今日工作台
家庭股票池
单股分析
数据同步
候选发现
设置
```

### 12.1 今日工作台

只放今天必须看的内容。

不要放全量列表。

### 12.2 家庭股票池

用表格或紧凑卡片展示：

- 名称。
- 状态。
- 标签。
- 结论。
- 数据健康。
- 当前价格。
- 关键价位。
- 最近变化。

点击进入单股分析页。

### 12.3 单股分析

这是系统主页面。

必须做到：

- 先结论，后证据。
- 先变化，后全量。
- 先风险，后机会。
- 所有图表都服务于判断。

### 12.4 家庭股票池管理

家庭股票池是第一版主入口，不再拆成“我的股票”和“爸爸的股票”。

适合家庭共同使用：

- 输入股票代码。
- 系统自动分析。
- 输出清晰结论。
- 不强制要求成本和仓位。
- 支持状态和标签管理。

### 12.5 数据同步

负责可信度。

任何单股结论都能追溯到这里。

### 12.6 候选发现

辅助模块。

只把高质量线索推给用户确认。

## 13. 技术架构建议

### 13.1 前端

默认选择：

- React + Vite + TypeScript。
- 单页应用。
- 路由支持单股详情页。
- Lightweight Charts 做 K 线和关键价位叠加。
- ECharts 做辅助图表，例如估值、财务趋势和情景路径。

选择理由：

- K 线展示更成熟。
- 可以叠加关键价位、中枢区间和情景路径。
- 更适合投研图表。

### 13.2 后端

默认选择：

- Python 负责数据同步和 AKShare 调用。
- Node/TypeScript 负责前端开发和轻量 API。
- 数据同步任务独立出来。
- 本地开发先用 SQLite。
- 后续可升级 PostgreSQL。

### 13.3 数据层

核心表建议：

- `stocks`：股票基础信息。
- `family_pool`：家庭股票池，记录状态和标签。
- `quotes`：行情快照。
- `bars_daily`：日线。
- `bars_weekly`：周线。
- `bars_60m`：60 分钟线。
- `financials`：财务指标。
- `valuations`：估值指标。
- `announcements`：公告。
- `chanlun_structures`：缠论结构。
- `stock_conclusions`：系统结论历史。
- `scenario_paths`：情景路径图数据。
- `manual_notes`：人工复盘记录。

数据层建议分三层：

- Raw Data：行情、K 线、财务、公告原文。
- Derived Data：技术指标、缠论结构、估值分位、关键价位。
- Decision Layer：结论、风险提醒、路径推演、人工复盘。

## 14. 第一阶段开发范围

建议新项目第一阶段不要贪大。

### Phase 1：家庭股票池 MVP

目标：

- 输入股票代码。
- 维护家庭股票池。
- 支持股票状态和标签。
- 同步真实行情、日线、周线和 60 分钟 K 线。
- 生成单股基础分析页。
- 输出数据健康状态。
- 输出基础结论层。

交付：

- 股票录入。
- 家庭股票池列表。
- 数据同步。
- 单股详情页。
- 数据健康卡。
- 基础结论卡。

Phase 1 暂缓：

- 完整财务深度分析。
- 完整估值分位。
- 公告深度解析。
- 完整情景路径图。
- 全市场候选发现。

### Phase 2：缠论和关键价位

目标：

- 周线、日线、60 分钟联动。
- 中枢、背驰、买点候选、风险卖点。
- 关键价位卡。

交付：

- 缠论结构区。
- 关键价位区。
- 结构变化提醒。

### Phase 3：情景路径图

目标：

- 强势路径。
- 震荡路径。
- 风险路径。
- 每条路径的成立和失效条件。

交付：

- 单股情景路径图。
- 路径解释文本。
- 图上标注关键价位和中枢。

### Phase 4：财务、估值、公告

目标：

- 基本面和事件进入结论层。
- 不同行业采用不同指标。

交付：

- 财务质量区。
- 估值区。
- 公告事件区。
- 行业专属分析。

### Phase 5：今日提醒

目标：

- 每日只提醒变化。

交付：

- 今日工作台。
- 风险/机会/数据异常提醒。

### Phase 6：候选发现

目标：

- 旧项目中的全市场筛选能力作为辅助线索。

交付：

- 候选发现页。
- 加入家庭股票池确认流。
- 入选理由卡。

## 15. 旧项目迁移策略

可以迁移：

- 股票代码标准化逻辑。
- AKShare 数据抓取经验。
- K 线解析和 60 分钟线逻辑。
- 技术指标计算。
- 缠论初版算法。
- 估值和财务指标计算。
- 公告解析思路。
- 数据健康检查。
- 测试用例思路。

不建议迁移：

- 当前混杂的页面结构。
- 旧 Dashboard 的全行业主导航。
- 旧的宽泛股票池主流程。
- 旧的投资者账户隔离模型。
- 为 MVP 临时设计的示例字段。
- 过度拥挤的卡片布局。

## 16. 新项目成功标准

第一阶段成功不是“覆盖多少只股票”，而是：

- 家庭股票池输入 5-20 只股票后，系统能稳定同步数据。
- 每只股票能生成清晰、可解释的结论。
- 数据不足时系统敢于说“不足以判断”。
- 单股页面能让用户 3 分钟内理解当前状态。
- 每天只提醒真正变化的内容。
- 家庭股票池可以作为主入口使用。
- 情景路径图能帮助用户理解强势、震荡和风险三种可能。

## 17. 推荐下一步

建议下一步按这个顺序做：

1. 确定新项目名称和目录。
2. 确定技术栈。
3. 设计新项目数据模型。
4. 画出第一版页面信息架构。
5. 从旧项目迁移最小数据同步能力。
6. 先做“输入股票代码 -> 加入家庭股票池 -> 同步数据 -> 单股分析页”闭环。
7. 再加入缠论和情景路径图。

最重要的是：新项目从第一天就围绕“单股深度分析”设计，不再围绕“全市场海选 Dashboard”设计。
